### A5 性能：200 个图形流畅 ✅ 2026-11-08

- **完成标准**：拖动一帧 ≤ 16 ms（60 帧），选中 / 框选 ≤ 100 ms；超了就优化（比如减少每帧的整板重绘、缓存板件识别结果），优化前后的数字都记在这里。

| 步骤（200 个图形） | 优化前 | 优化后 | 标准 |
|---|---|---|---|
| 选中（单击） | 142 ~ 173 ms | 42 ~ 61 ms | ≤ 100 ms |
| 拖动一帧（中位数 / 95%） | 32 ~ 34 / 50 ~ 53 ms | 13 ~ 15 / 24 ~ 28 ms | ≤ 16 ms |
| 拖缩放手柄一帧（中位数 / 95%） | 32 ~ 33 / 40 ~ 51 ms | 13 ~ 14 / 18 ~ 32 ms | ≤ 16 ms |
| 框选（选中 100 个） | 39 ~ 43 ms | 7 ~ 10 ms | ≤ 100 ms |
| 拖完松手（提交） | 43 ~ 47 ms | 26 ~ 36 ms | — |
| 滚轮缩放视图 | 3 ms | 3 ms | — |

- **做了什么**：① 判断轮廓嵌套（`loopDepths`）时，200 个轮廓两两比较的外框改成先算好的数字（原来每次都访问 paper 的 bounds）；② 拖动中不再每帧重新识别板件（松手提交时再更新「识别到 N 块板」）；③ 自相交面积（A3 加的）按「面积 + 周长」缓存，移动时不重算；④ 只改选中、图形没变时不重画板面，同一个已提交状态只识别一次板件；⑤ 单击选中、没拖动时不再提交（省一次 200 个图形的序列化）。

3. **不改界面布局、不加新功能、不改产品流程。** 需要改的话，写进「待你决定」，然后跳过。
4. 每修一个问题，先写一个能复现它的测试（修之前测试失败，修之后通过）。
5. 提交前跑全部测试（`tests/e2e/run.sh`、`tests/py`、`tests/js`），全部通过才提交。
6. 提交信息写清楚改了什么，以及证据（测试名）；在本文件对应的任务上打勾，写上证据和日期；`CHANGELOG.md` 的「未发布」加一行。
7. 改脚本后检查可执行权限（`.command` / `.sh`）。
8. 结束时在本文件「状态」里更新「最近一次运行」：做了什么、哪些还没验证。缺数据就写「未验证」，不推测。
